AlphaPay Open API v2.0 Webhook (2.0)

Download OpenAPI specification:

平台向商户发送的异步通知。商户需提供公网可访问的 notifyUrl，以平台公钥验签后处理， 并返回结构化的成功应答。

同一通知可能多次送达，商户系统须幂等处理：支付通知以 paymentId 识别，退款通知以 refundId 识别。 同一订单的多笔部分退款是不同的退款单，各有不同的 refundId。

订单金额与状态以订单查询接口的结果为准，退款结果以退款查询接口的结果为准；通知用于触发查询，不作为最终依据。

支付成功通知 Webhook

订单支付成功、且下单时传入 notifyUrl 时推送。body 为订单查询响应中除 result 以外的业务字段。 每笔订单只在支付成功时产生一条支付成功通知；支付失败或未支付即关闭的订单不推送通知，其状态以订单查询接口为准。

本通知的内容为付款成功时的订单信息，不随该订单之后的退款变化；部分或全额退款以退款查询接口为准。

重试：商户未返回成功应答时，平台自付款成功起约 24 小时内按递增间隔重试，同一通知可能多次送达。 商户系统应以 paymentId 识别并处理重复通知，不依赖固定的推送次数或间隔；订单状态以订单查询接口为准。

退款结果通知 Webhook

退款被支付渠道受理、且发起退款时传入 notifyUrl 时推送，该笔退款自此计入商户账务与结算。 body 为退款查询响应中除 result 以外的业务字段。推送地址为发起退款时传入的 notifyUrl，不沿用下单时传入的地址。

每笔退款推送一条通知：同一订单的多笔部分退款各推送一条，商户系统应以 refundId（而非 paymentId）识别并处理重复通知。 本通知的 refundStatus 始终为 SUCCESS，表示退款已被支付渠道受理，不表示款项已退回付款人（见 refundStatus 字段说明）。 未被受理即失败、审核未通过的退款不推送；受理后退款失败的，平台不再就此推送通知。退款最终结果以退款查询接口为准。

重试：与支付通知相同，平台自退款被受理起约 24 小时内按递增间隔重试，同一通知可能多次送达。 商户系统不应依赖固定的推送次数或间隔。
