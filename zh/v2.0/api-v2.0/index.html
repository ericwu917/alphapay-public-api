AlphaPay Open API v2.0 (2.0)

Download OpenAPI specification:

面向外部商户的 RSA2（SHA256withRSA）开放支付 API。 统一 base path /api/v2.0；请求 / 响应体均为 application/json。 所有端点均为 POST。

请求须带 Content-Type: application/json; charset=UTF-8 与 Accept: application/json 两个头。 请求与响应均使用 RSA2 签名：平台以商户公钥验证请求签名，并以平台私钥对响应签名，详见安全方案 gatewaySignV2。

统一下单

统一下单，按 scenarioCode 区分支付场景。

统一下单（按 scenarioCode 受理 11 种支付场景）

创建支付订单并返回支付凭据 paymentInfo（按场景返回支付页地址、二维码或 SDK 参数）。 同一 Merchant-Code 下以 paymentRequestId 作为幂等键：以同一 paymentRequestId 重复下单不会新建订单， 返回该订单的当前结果，请求内容与首次不同时同样如此——订单已支付时 resultCode 为 ORDER_PAID， 等待支付时 resultStatus 为 U、resultCode 为 PAYMENT_IN_PROCESS。 各 scenarioCode 的必填字段见请求体结构中按场景列出的条件。

受理成功且尚未得出支付结果时，result.resultStatus 为 U、resultCode 为 PAYMENT_IN_PROCESS； 已同步得出支付结果时为 S 或 F。 支付结果以订单查询接口的结果为准，支付通知用于触发查询。 业务失败时返回 HTTP 200，result.resultStatus 为 F，resultCode 取值见 Result。

Apple Pay

Apple Pay 两步支付：预下单与扣款。

Apple Pay 预下单（第一步，返回唤起 Apple Pay sheet 参数）

Apple Pay 支付的第一步，使用独立接口，不经统一下单的 scenarioCode：创建订单并返回 applePayParams， 供客户端唤起 Apple Pay sheet。成功时 resultStatus 为 U（resultCode 为 PAYMENT_IN_PROCESS）。 Apple Pay 订单在订单查询与支付成功通知中的 scenarioCode 为 CREDIT_CARD。

同一 Merchant-Code 下以 paymentRequestId 作为幂等键，以同一 paymentRequestId 重复预下单的处理同统一下单。 orderAmount.value 以给定币种的最小计价单位表示；对有两位小数的币种，100 表示 1.00。

退款

对已支付订单按金额退款。

按金额发起退款

对已支付订单按金额退款；单笔订单可分多次退款，退款总额不得超过实际支付金额。 退款币种与原订单相同，请求金额不含 currency 字段。 主商户开通相应权限后，可为其子商户的订单发起退款；同一主商户下开通互退的子商户之间可互相发起退款。

refundRequestId 为商户退款单号（必填），在订单所属商户范围内作为幂等键： refundRequestId 相同的重复提交返回首次受理的结果，不重复退款； refundRequestId 已用于其他订单，或与首次提交的金额不一致，返回 REFUND_MISMATCH。 退款失败后以新的 refundRequestId 重新发起。

受理成功时 resultStatus 为 S、resultCode 为 SUCCESS，并返回平台退款单号 refundId； 退款最终结果以退款查询接口的结果为准，退款通知用于触发查询。 退款进入平台审核时 resultCode 为 REFUND_NEED_REVIEW、resultStatus 为 U，响应含 refundId； 审核结果以退款查询为准；请求传入 notifyUrl 时，审核通过且退款被渠道受理后推送退款通知。 退款已建立、渠道尚未给出受理结论时 resultCode 为 REFUND_IN_PROCESS、resultStatus 为 U，响应含 refundId；最终结果以退款查询为准。 处理结果未知时（如平台内部错误）resultStatus 为 U，以退款查询确认。

退款被拒时 resultStatus 为 F，常见结果码：

  • ORDER_NOT_EXIST：订单不存在，或不在本商户可发起退款的范围内。
  • ORDER_NOT_PAID：订单尚未支付。
  • ORDER_CLOSED：订单已关闭或支付失败。
  • INVALID_REFUND_AMOUNT：退款金额超出该订单当前可退金额。
  • FULL_REFUND_COMPLETED：该订单已全额退款。
  • EXIST_PROCESSING_REFUND：该订单的前一笔退款仍在创建中，可稍后重试或调用退款查询。
  • REFUND_VALID_DATE_EXCEED：订单已超出可退期限。
  • REFUND_NOT_ENOUGH_BALANCE：商户可用余额不足以支付本次退款，退款失败，响应含该笔失败退款的 refundId；补足余额后以新的 refundRequestId 重新发起。
  • REFUND_NO_PERMISSION：该商户未开通退款。
  • MERCHANT_FROZEN：该商户已被平台暂停交易。
  • PRE_AUTH_ORDER：预授权订单不可经本接口退款。
  • REFUND_MISMATCH：该 refundRequestId 已用于其他订单，或与首次提交的金额不一致。

关单（关闭未支付订单）

关闭尚未支付的订单，关闭后订单状态为 CLOSED，付款人不能再对该订单付款，不涉及资金。 订单已关闭、已失效或已失败时同样返回 resultStatus 为 S。

不能关闭时 resultStatus 为 F，常见结果码：

  • ORDER_PAID：订单已支付；需要退还款项时调用退款接口。
  • ORDER_NOT_EXIST：订单不存在。
  • ORDER_CANCEL_FAILED：订单关闭失败。
