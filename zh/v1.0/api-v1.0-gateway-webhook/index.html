AlphaPay Open API v1.0 Webhook (1.0)

Download OpenAPI specification:

平台向商户发送的异步通知。商户需提供公网可访问的 notify_url，按 v1.0 签名算法重新计算 body 内的 sign 并比对，处理后返回规定的成功应答。

同一通知可能多次送达，商户系统须幂等处理： 支付通知以平台订单号识别，退款通知以平台退款号识别，委托代扣签约状态通知以 data 中的 clientContractNo 与 state 识别。

金额单位：通知中的金额以给定币种的最小计价单位整数表示（对有两位小数的币种，100 表示 1.00）， 支付通知的 clearing_amount 例外，以元（币种主单位小数）表示，见该字段说明。

订单金额与状态以订单查询接口的结果为准，退款结果以退款查询接口的结果为准，合约状态以合约查询接口的结果为准；通知用于触发查询，不作为最终依据。

支付与退款通知

支付 / 退款通知（校验三要素在 body 内；应答规则相同：任意 2xx，不要求响应体）

支付成功通知 Webhook

下单或委托代扣扣款时传入 notify_url、且订单支付成功时推送，每笔订单推送一条支付通知。 支付失败或未支付即关闭的订单不推送，其状态以订单查询接口的结果为准。 通知内容为支付成功时的订单信息，不随该订单之后的退款变化。

签名：通知不带签名头，校验三要素 time / nonce_str / sign 位于 body 内。 sign 以商户编码（partner_code）、time、nonce_str 与 credential_code 按与 API 请求签名相同的算法计算。 订单金额与状态以订单查询接口的结果为准。

重试：商户未返回 2xx 时，平台自付款成功起约 24 小时内按递增间隔重试。 通知地址返回 307 或 308 跳转时，平台按原报文向跳转后的地址重发；返回其他跳转时视为未送达。 商户系统应以 order_id 识别并处理重复通知。

退款结果通知 Webhook

退款被支付渠道受理、且发起退款时传入 notify_url 时推送，该笔退款自此计入商户账务与结算。 每笔退款推送一条退款通知；同一订单的多笔部分退款各推送一条，以 refund_id 区分。 通知地址取自退款请求中的 notify_url，不沿用下单请求中的 notify_url。 退款通知包含退款查询接口的业务字段，以及 time、nonce_str、sign 和 channel，字段与支付通知不同； 签名与验签方式同支付通知。商户系统应以 refund_id 识别并处理重复通知。

本通知的 result_code 为 SUCCESS，表示退款已被支付渠道受理，不表示款项已退回付款人； 退款的最终结果以退款查询接口为准。

本通知仅在退款被受理时推送；退款未被受理（含审核未通过）或受理后失败时不推送，结果以退款查询接口的结果为准。

重试：与支付通知相同。商户未返回 2xx 时，平台自退款被受理起约 24 小时内按递增间隔重试；跳转的处理同支付通知。

委托代扣签约状态通知

委托代扣签约状态通知（校验三要素在 body 内；应答体顶层 code 须为 SUCCESS）

委托代扣签约状态通知 Webhook

合约在渠道侧的状态发生变化时推送，包括三类：签约成功、签约失败与解约，每次变化推送一条。 解约包括付款人撤销授权、渠道终止合约，以及已生效的合约经商户调用解约接口解除。 以下情形不推送，合约状态通过合约查询确认：签约未能发起、付款人未在签约有效期内完成授权、合约有效期届满。

data 为合约信息经 JSON 序列化后的字符串，不是嵌套对象，需先反序列化再读取字段；所含的键见请求体中 data 字段的说明。

签名：校验三要素 time / nonce_str / sign 位于 body 内，sign 的计算方法同支付通知。

重试：商户未返回成功应答时，平台自合约状态变化起约 24 小时内按递增间隔重试，同一通知可能多次送达。 通知地址返回跳转时视为未送达。商户系统应以 data 中的 clientContractNo 与 state 识别并处理重复通知。
