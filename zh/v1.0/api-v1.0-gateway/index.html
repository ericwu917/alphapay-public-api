AlphaPay Open API v1.0 (1.0)

Download OpenAPI specification:

面向外部商户的 v1.0 gateway 对称签名支付 API。 base path /api/v1.0。 请求以对称签名认证：签名三要素 time、nonce_str、sign 以 query 参数传递，算法见安全方案 gatewaySignV1。

请求头：除支付页（浏览器入口，见「支付页约定」）外，请求头 Accept 须为 application/json； PUT / POST 请求的 Content-Type 须为 application/json；字符集 UTF-8。 Accept 含 text/html 时，失败结果不以 JSON 错误信封返回，而是跳转至平台错误页。

时间与日期：本 API 所有 yyyy-MM-dd HH:mm:ss / yyyyMMddHHmmss 时间字段与 yyyyMMdd 日期 （含订单列表与交易流水的查询参数 date）均按 UTC-8；结算记录查询的 date 为结算日。

金额单位：本 API 的金额默认以给定币种的最小计价单位整数表示（对有两位小数的币种，100 表示 1.00）。 下列三处例外，单位为元（币种主单位小数，如 10.50）：

  • 订单列表（listOrders）响应 data[] 与 analysis 中的金额；
  • 卡支付预下单（createCardOrder）请求的 amount 与 tipAmount；
  • 支付通知的 clearing_amount（见 Webhook 参考）。

错误提示多语言：系统错误提示支持中文 / 英文，按请求头 Accept-Language 自动选择。 仅影响错误提示文案——错误码 return_code 与业务字段不随语言变化。

下单通用规则

各下单接口的通用规则：

  • 商户订单号（path order_id）在同一商户下唯一。以同一订单号重复下单不会新建订单，按下列规则处理：
    • 该单已支付：返回 ORDER_PAID；
    • 该单已关闭：返回 ORDER_CLOSED；
    • 该单正在处理，或同一订单号并发下单：返回 DUPLICATE_ORDER_ID；
    • 其余情形（含请求内容与首次下单不同）返回该单既有结果（result_code=EXISTS），订单内容以首次下单为准。
  • 订单有效期：未支付订单超过有效期即失效（默认 5 分钟，商户可在商户后台调整）。 以失效订单的订单号再次下单同样按上条处理、不会重新开单；需要重新收款时以新的商户订单号下单。
  • 订单描述 description：上限 128 字符。
  • 请求字段格式：currency 为标价币种，可用的标价币种以商户开通情况为准（至少含商户的结算币种与 CNY），省略时取商户的结算币种； notify_url 须以 http:// 或 https:// 开头，且只含字母、数字、下划线与 . - / : ? & =； redirect 须为带协议头的完整地址（如 https://…）。 不符合时返回 PARAM_INVALID。
  • CNY 标价：以 CNY 标价的订单折合结算币种后须不低于 0.01。
  • 支付页：响应中的 pay_url 指向本 API 的支付页（见「支付页约定」）；跳转至校验签名的支付页前，商户须在其上追加签名三元组与 redirect；无需签名的入口见各入口说明。详见 pay_url 字段说明。
  • 错误码（return_code）：通用码见 GatewayErrorV1；另有 ORDER_PAID / ORDER_CLOSED / DUPLICATE_ORDER_ID；H5 下单另有 SECONDARY_MERCHANT_ID_INVALID；付款码被扫另有 AUTHCODEEXPIRE / NOTENOUGH / NOTSUPORTCARD / AUTH_CODE_ERROR / AUTH_CODE_INVALID。

支付页约定

支付页（浏览器入口，非 JSON API）。下单响应的 pay_url 指向这些入口；商户在其上追加 query 签名三元组 （time / nonce_str / sign，每次跳转重新生成）与 redirect 后，把付款人浏览器带到该地址。 付款人在页内完成支付后，浏览器按 redirect 跳回商户页面。跳回不代表支付成功，支付结果以订单查询的结果为准。

本参考约定的是入口路径、query 参数、错误码与按 redirect 跳回；页面呈现、页内交互与中间跳转链（含 302 的目标地址）不属于约定。

签名与重复打开：校验签名的支付页对签名三元组的时间窗要求与 API 接口相同（time 与服务器时间相差须小于 5 分钟）。 同一商户同一组 time + nonce_str 在首次使用时与所请求的地址绑定：同一支付页地址可用这组要素在时间窗内重复打开 （付款人刷新、返回不会被拒）；这组要素用于其他地址或任一 API 接口时返回 SIGN_EXPIRED。 部分支付页无需签名，见各入口说明。支付页忽略各入口未列出的查询参数。

错误码（return_code）：ORDER_NOT_EXIST；订单已支付返回 ORDER_PAID，已关闭返回 ORDER_CLOSED； 以及 GatewayErrorV1 所列通用码。 浏览器请求（Accept 含 text/html）失败时跳转至平台错误页，不返回 JSON 错误信封。

浏览器下单

付款人在浏览器中完成支付的下单：扫码、原生二维码、Online、银联在线、支付宝网关、Alipay+、H5、卡支付预下单。通用规则见概览「下单通用规则」。

退款

创建退款与查询退款状态。

创建退款

对已支付订单退款。refund_id（商户退款号）为必填路径参数，用作幂等键。请求 fee 与响应 amount 均以给定币种的最小计价单位表示；对有两位小数的币种，100 表示 1.00。

path order_id 也可传平台订单号或银联交易号，解析方式同单订单查询。

幂等：退款号在订单所属商户范围内唯一。同一退款号重复提交不会重复退款，返回首次受理的结果，响应另带该退款当前的 result_code；首次因商户可用余额不足失败或进入审核的，重复提交返回该笔退款及其当前 result_code （如 CREATE_FAILED、WAITING）。退款号已用于其他订单，或与首次提交的金额不一致，返回 REFUND_MISMATCH。 一个退款号只对应一笔退款，退款失败后以新的退款号重新发起。

退款规则：一笔订单可多次退款；各次退款累计金额不得超过该订单的实际支付金额 （单订单查询的 real_fee——付款人支付的服务费同样可退）；退款币种与原订单相同。 主商户开通相应权限后，可为其子商户的订单发起退款；同一主商户下开通互退的子商户之间可互相发起退款。

错误码（return_code）：下列码，以及 GatewayErrorV1 所列通用码。

  • ORDER_NOT_EXIST：订单不存在，或不在本商户可退款的范围内。
  • ORDER_NOT_PAID：订单尚未支付。
  • ORDER_CLOSED：订单已关闭或支付失败。
  • REFUND_MISMATCH：退款号已用于其他订单，或与首次提交的金额不一致。
  • INVALID_REFUND_AMOUNT：退款金额超出该订单当前可退金额。
  • FULL_REFUND_COMPLETED：该订单已全额退款。
  • EXIST_PROCESSING_REFUND：该订单的前一笔退款仍在创建中，可稍后重试或调用退款查询。

委托代扣签约（App）

为付款人创建一份委托代扣合约，并返回商户 App 调起渠道签约所需的会话参数。 付款人在渠道内确认授权后合约生效，此后商户系统可依据该合约发起扣款。

contract_no 为商户合约号，在同一商户下唯一，以路径参数为准（请求体内同名字段被忽略）。 同一商户合约号只能提交一次：重复提交返回 DUPLICATE_ORDER_ID，不返回首次结果，也不覆盖原合约； 签约未能发起时该商户合约号同样不可再次使用。重新签约须使用新的商户合约号。

受理成功时返回合约查询结构，result_code 为 NOTSIGN，sdk_params.session_id 为调起签约的会话标识。 签约成功、签约失败与解约经签约状态通知送达；签约未能发起、付款人未在签约有效期内完成授权， 以及合约有效期届满时不推送通知。合约状态以合约查询的结果为准。

委托代扣扣款

依据已签约的合约发起一笔扣款，付款人无需确认。price 以给定币种的最小计价单位表示； 对有两位小数的币种，100 表示 1.00。

受理成功时返回 return_code=SUCCESS、result_code=PAYING，响应结构与单订单查询相同（OrderQueryResultV1，扣款订单各字段取值见本接口 200 响应说明）； 平台未受理该笔扣款时 result_code 为 CREATE_FAIL。扣款被渠道拒绝时，订单查询返回 result_code=PAY_FAIL， 并带 channel_error_code 与 channel_error_message。扣款结果以订单查询的结果为准，支付通知用于触发查询。

同一商户订单号只对应一笔扣款。以同一订单号重复提交时不会重复扣款，按该订单当前状态返回： 处理中返回 return_code=SUCCESS 与 result_code=PAYING；已支付返回 ORDER_PAID；已关闭、失败或未受理返回 ORDER_CLOSED。 该订单号已用于下单接口创建的订单，或合约号、金额、币种与已有扣款不一致时返回 PARAM_INVALID，不发起扣款。

结果通知：请求带 notify_url 时，扣款成功后平台向该地址发送支付通知，通知内容与下单接口的支付通知相同。

错误码（return_code）：合约不存在、不属于本商户或不可用于扣款（含未处于 SIGNED 状态）返回 CONTRACT_NOT_EXIST； 商户当前不可受理该扣款返回 NOT_PERMITTED；同一订单号的处理见上；以及 GatewayErrorV1 所列通用码。
